# Rancangan Pembelajaran Terdiferensiasi — Fase F Kelas 12
## Materi: Proyek Capstone Rekayasa Perangkat Lunak

---

### 1. Tujuan Pembelajaran

1.1 Menerapkan seluruh siklus proses rekayasa (SDLC) dalam proyek nyata: analisis → desain → pengembangan → pengujian → *deployment* → penyempurnaan.  
1.2 Merancang solusi berbasis teknologi untuk masalah nyata di lingkungan sekitar.  
1.3 Mengembangkan produk teknologi digital (aplikasi/*website*/sistem IoT) secara kolaboratif dalam tim.  
1.4 Menerapkan strategi algoritmik dan struktur data kompleks dalam pengembangan produk.  
1.5 Melakukan pengujian dan *quality assurance* untuk memastikan kualitas produk.  
1.6 Menyusun dokumentasi teknis dan panduan pengguna.  
1.7 Mempresentasikan dan mempertahankan produk di depan audiens (*project exhibition*).

### 3. Asesmen Awal

#### 3.1 Instrumen Asesmen Awal

**Bentuk:** Proposal ide + *self-assessment* kesiapan + wawancara minat.

**Proposal Ide (Format Bebas):**
> "Tuliskan ide produk teknologi digital yang ingin kamu buat untuk menyelesaikan masalah di sekolah/lingkunganmu. Sertakan: (1) masalah yang diangkat, (2) solusi yang ditawarkan, (3) fitur utama, (4) teknologi yang akan digunakan!"

***Self-Assessment* Kesiapan Teknis:**
| Area | Belum Siap | Cukup Siap | Siap |
|------|-----------|-------------|------|
| Pemrograman (Python/Web/Mobile) | | | |
| Basis data / penyimpanan data | | | |
| Desain antarmuka (UI/UX) | | | |
| Pengujian dan *debugging* | | | |
| Kerja tim dan manajemen proyek | | | |
| Presentasi dan dokumentasi | | | |

**Wawancara Minat:**
> Tanyakan: topik proyek yang diminati, peran yang diinginkan dalam tim (*project manager*, *developer*, *designer*, *tester*), dan target hasil.

#### 3.2 Kriteria Kesiapan Belajar

| Kondisi | Kategori | Tindak Lanjut |
|---------|----------|---------------|
| Ide belum spesifik, *self-assessment* banyak "belum siap", belum punya peran | **Kurang Siap** | Bimbingan pemilihan topik, pendampingan teknis ekstra, peran yang sesuai kemampuan |
| Ide cukup jelas, *self-assessment* bervariasi, punya preferensi peran | **Cukup Siap** | *Scaffolding* perencanaan proyek, *checklist* kemajuan, *mentoring* berkala |
| Ide spesifik dan inovatif, *self-assessment* "siap" di area utama, peran jelas | **Sudah Siap** | Kebebasan eksplorasi, *milestone* proyek, *code review*, tantangan fitur tambahan |

### 4. Rancangan Diferensiasi

#### 4.1 Diferensiasi Konten dan Projek

| Kelompok | Jenis Proyek | Kompleksitas |
|----------|-------------|--------------|
| **Kurang Siap** | Aplikasi sederhana (kalkulator lanjut, *to-do list*, *note taking*) dengan *template* yang disediakan | Terstruktur, *template* disediakan, fitur minimal |
| **Cukup Siap** | Aplikasi/website dengan fungsi *CRUD*, antarmuka pengguna, dan penyimpanan data (misal: sistem perpustakaan kelas, buku tamu digital) | Semi-kompleks, desain sendiri, fitur standar |
| **Sudah Siap** | Produk inovatif dengan integrasi API/AI/IoT/*cloud* (misal: sistem monitoring kebun IoT, aplikasi deteksi sentimen, *dashboard* data *real-time*) | Kompleks, inovatif, integrasi teknologi lanjut |

#### 4.2 Diferensiasi Proses

| Kelompok | Aktivitas Pembelajaran | Pendampingan |
|----------|------------------------|--------------|
| **Kurang Siap** | *Sprint* pendek (1 minggu per tahap): analisis → desain → *coding* → uji → revisi. *Template* dokumen dan kode disediakan | Pendampingan intensif, *daily check-in*, *pair programming* dengan pendidik/tutor |
| **Cukup Siap** | *Sprint* 2 mingguan: *milestone* jelas, *code review* mingguan, *peer feedback* | *Scaffolding* berupa *checklist* dan *template* dokumen, *mentoring* berkala |
| **Sudah Siap** | *Agile/scrum*: *sprint planning* → *daily standup* → *sprint review* → *retrospective*. Produk siap *deploy* | Mandiri, pendidik sebagai *product owner*/*scrum master* |

#### 4.3 Diferensiasi Produk

| Kelompok | Bentuk Produk Akhir | Kriteria Minimal |
|----------|---------------------|------------------|
| **Kurang Siap** | Program berfungsi (lokal) + dokumentasi *readme* + presentasi 5 menit | Berjalan, 3 fitur utama, dokumentasi dasar |
| **Cukup Siap** | Program + antarmuka pengguna + penyimpanan data + dokumentasi teknis + *slide* presentasi | *CRUD*, UI *user-friendly*, dokumentasi, demo |
| **Sudah Siap** | Produk siap pakai/*deploy* + dokumentasi lengkap + *user guide* + presentasi + *video demo* | *Deployed*, fitur inovatif, dokumentasi profesional, presentasi meyakinkan |

---

### 5. Pengelompokan Fleksibel

- Tim dibentuk berdasarkan minat proyek dengan komposisi heterogen (campuran tingkat kesiapan).
- Rotasi peran setiap *sprint* jika memungkinkan untuk pengembangan kompetensi.
- *Daily standup* 5 menit setiap awal jam pelajaran untuk memantau kemajuan.
- *Sprint review* presentasi di akhir setiap tahap.

### 6. Asesmen Sumatif (Akhir Proyek)

| Indikator | Perlu Perbaikan | Cukup | Baik | Sangat Baik |
|-----------|----------------|-------|------|-------------|
| Perencanaan proyek | Tidak ada rencana | Rencana minimal | Rencana lengkap (tujuan, fitur, jadwal, pembagian peran) | Rencana + *risk management* + *milestone* |
| Implementasi teknis | Tidak berfungsi | Sebagian fitur berfungsi | Semua fitur berfungsi | Fitur berfungsi + optimal + *error handling* |
| Kualitas produk | Banyak *bug* | Beberapa *bug* minor | Minim *bug*, UI rapi | Produk siap pakai, UI/UX baik |
| Dokumentasi | Tidak ada | *Readme* minimal | Dokumentasi teknis + *user guide* | Dokumentasi lengkap + *deployment guide* |
| Presentasi | Tidak siap | Presentasi cukup | Presentasi jelas + demo | Presentasi profesional + demo + tanya jawab |
| Refleksi | Tidak ada | Refleksi singkat | Refleksi proses + hasil | Refleksi + rencana pengembangan lanjutan |
| Kerja tim | Tidak partisipasi | Partisipasi pasif | Kontribusi aktif | Kepemimpinan + fasilitasi tim |
