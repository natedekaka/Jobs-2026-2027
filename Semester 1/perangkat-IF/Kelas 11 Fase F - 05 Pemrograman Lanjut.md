# Rancangan Pembelajaran Terdiferensiasi — Fase F Kelas 11
## Materi: Algoritma dan Pemrograman Lanjut

---

### 1. Tujuan Pembelajaran

1.1 Memahami konsep strategi algoritmik dalam pemrograman.  
1.2 Mengembangkan program komputer terstruktur, modular, efektif, efisien, dan optimal.  
1.3 Mengembangkan, melakukan pemeliharaan, dan penyempurnaan algoritma standar ke dalam kode sumber program.  
1.4 Memperhatikan kualitas program (*readability*, *maintainability*, *efficiency*).  
1.5 Merancang dan mengimplementasikan program dengan struktur data kompleks.  
1.6 Menggunakan *library* atau perangkat yang tersedia, termasuk modul AI.  
1.7 Mengintegrasikan program dengan perangkat lain (IoT, robot fisik, atau API).

---

### 2. Kompetensi Prasyarat

| No | Kompetensi Prasyarat | Keterkaitan |
|----|----------------------|-------------|
| 1 | Peserta didik mampu menulis pseudocode dan program sederhana (Fase E) | Dasar pemrograman lanjut |
| 2 | Peserta didik memahami struktur data (list, stack, queue) (Fase E) | Prasyarat struktur data kompleks |
| 3 | Peserta didik memahami strategi algoritmik dasar (materi sebelumnya) | Prasyarat implementasi strategi dalam kode |
| 4 | Peserta didik mampu menggunakan *spreadsheet*/*tools* digital | Prasyarat eksplorasi *library* |

---

### 3. Asesmen Awal

#### 3.1 Instrumen Asesmen Awal

**Bentuk:** Praktik *coding* diagnostik + soal pemahaman konsep + *self-assessment*.

**Praktik Coding Diagnostik:**
> Berikan soal berikut dalam bahasa Python (atau bahasa yang diajarkan):
> ```
> 1. Buat program yang menerima 3 angka dan mencetak angka terbesarnya!
> 2. Buat program yang mencetak deret Fibonacci hingga suku ke-n!
> ```

**Soal Konsep:**
1. "Apa perbedaan program terstruktur dan tidak terstruktur?"
2. "Apa yang dimaksud dengan *library*/*module* dalam pemrograman? Berikan contoh!"
3. "Bagaimana cara mengukur kualitas sebuah program?"

***Self-Assessment*:**
- [ ] Saya bisa menulis program dengan fungsi/prosedur
- [ ] Saya pernah menggunakan *library* pihak ketiga
- [ ] Saya paham konsep *array*/*list* multidimensi
- [ ] Saya pernah membuat program yang terhubung ke *file*/*database*
- [ ] Saya bisa membaca dan memperbaiki *error*/*bug*

#### 3.2 Kriteria Kesiapan Belajar

| Kondisi | Kategori | Tindak Lanjut |
|---------|----------|---------------|
| Kesulitan membuat program sederhana, belum memahami fungsi, *self-assessment* ≤ 1 | **Kurang Siap** | *Review* dasar pemrograman (variabel, percabangan, perulangan, fungsi sederhana) |
| Mampu membuat program sederhana, memahami fungsi, *self-assessment* 2-3 | **Cukup Siap** | Pengenalan modularisasi, *error handling*, dan penggunaan *library* dasar |
| Mampu membuat program dengan fungsi + *error handling*, *self-assessment* ≥ 4 | **Sudah Siap** | Struktur data kompleks, API/*library* AI, integrasi IoT, kualitas kode profesional |

### 4. Rancangan Diferensiasi

#### 4.1 Diferensiasi Konten

| Kelompok | Sumber Belajar | Kompleksitas |
|----------|---------------|--------------|
| **Kurang Siap** | Modul *review* dasar Python + kartu referensi sintaks + video tutorial fungsi + latihan bertahap | Review, bertahap, visual |
| **Cukup Siap** | Modul pemrograman modular + dokumentasi *library* standar + contoh proyek + panduan *debugging* | Semi-kompleks, aplikatif |
| **Sudah Siap** | Dokumentasi *library* AI/ML + tutorial API + studi kasus program produksi + kode sumber proyek *open source* | Kompleks, profesional, eksploratif |

#### 4.2 Diferensiasi Proses

| Kelompok | Aktivitas Pembelajaran | Pendampingan |
|----------|------------------------|--------------|
| **Kurang Siap** | *Pair programming* dengan tutor: menulis program sederhana → ditambah fungsi → ditambah *error handling* | Pendampingan intensif, *driver-navigator* |
| **Cukup Siap** | Proyek individu/berpasangan: program modular dengan 3-4 fungsi + menggunakan 1 *library* eksternal + dokumentasi | *Code review* berkala, *scaffolding* |
| **Sudah Siap** | Proyek mandiri: program dengan struktur data kompleks + *library* AI/API + integrasi perangkat lain + pengujian + *deployment* | Konsultasi sesuai kebutuhan, standar profesional |

#### 4.3 Diferensiasi Produk

| Kelompok | Bentuk Produk | Kriteria |
|----------|--------------|----------|
| **Kurang Siap** | Program kalkulator sederhana dengan fungsi (input, proses, output) + *error handling* | Program berjalan, fungsi minimal 3, *handle error* dasar |
| **Cukup Siap** | Program aplikasi dengan modularitas (min 5 fungsi) + menggunakan 1 *library* eksternal + dokumentasi | Modular, *library* eksternal, dokumentasi *readme*, *error handling* |
| **Sudah Siap** | Program dengan struktur data kompleks + *library* AI/API + integrasi IoT/*file*/*database* + *unit test* + dokumentasi teknis | Kode produksi, *tested*, terintegrasi, dokumentasi lengkap |

---

### 5. Pengelompokan Fleksibel

- *Pair programming* dengan rotasi *driver* dan *navigator* setiap 15 menit.
- Kelompok proyek dapat dibentuk berdasarkan minat (aplikasi *desktop*, *web*, *data*, AI, IoT).
- *Code review* lintas kelompok: setiap kelompok meninjau kode kelompok lain dan memberikan umpan balik.

### 6. Asesmen Sumatif (Akhir Materi)

| Indikator | Perlu Perbaikan | Cukup | Baik | Sangat Baik |
|-----------|----------------|-------|------|-------------|
| Program terstruktur | Monolitik | 2-3 fungsi | 4-5 fungsi modular | Modular + *reusable* |
| Kualitas kode | Tidak rapi | Rapi, tanpa komentar | Rapi + komentar + *naming* baik | Rapi + dokumentasi + *coding standard* |
| Penggunaan *library* | Tidak menggunakan | 1 *library* | 2-3 *library* | *Library* + API/AI/IoT |
| *Debugging* & *error handling* | Tidak ada | *Error handling* dasar | *Error handling* + *logging* | *Unit test* + *debugging* sistematis |
| Struktur data kompleks | *List* 1D | *List* 2D/*dict* | *Nested* struktur data | Struktur data + algoritma optimal |
| Dokumentasi | Tidak ada | 1 paragraf | *Readme* + *comment* | Dokumentasi teknis lengkap |
